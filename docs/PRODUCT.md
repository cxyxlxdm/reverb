# 余音 · Reverb 功能介绍

> 一款安静的多端播客客户端。**没有推荐流、没有广告、不需要注册、没有服务器。**
> 现有四个原生版本:**Android**(Kotlin / Compose)、**macOS**(Swift / SwiftUI)、
> **HarmonyOS**(ArkTS / ArkUI)、**iOS**(Swift / SwiftUI,经 TestFlight 分发,暂不上架 App Store)。
>
> 这份文档是**面向使用者与评审的完整介绍**:每个功能是什么、怎么用、在哪一端什么样。
> 需要逐项对照的开发用矩阵见 `FEATURES.md`(那份是权威清单,本文档不重复它的表格细节);
> 实现原理见 `ARCHITECTURE.md`。
>
> **Android 只有一份包**(2026-10-18 起;原先「自分发版 / 大陆商店版」两套功能范围不同,
> 起因是合规口径 —— 那段叙述见 `docs/HISTORY.md` 阶段五,合并的经过与验收记在
> `docs/TROUBLESHOOTING.md` H205)。现在同一份 `reverb.apk` 既交大陆应用市场、也放 GitHub Releases,
> **功能全开**。鸿蒙仍只有商店一种,macOS 自分发;端与端之间的差异见文末「渠道差异」一节,
> 凡有差异之处本文都会点明。

---

## 一句话说清它是什么

**你自己攒起来的播客库,保存在你自己的设备上。**

没有开发者后端意味着:没有账号可注册、没有云端可同步,本地数据不会自动上传给开发者。
订阅、历史、收藏、下载、批注、收听时长、印记全部保存在应用私有目录,卸载即删除。
应用联网时会把搜索词、地区或分类发给公开目录,并直接请求发布方或托管方的 RSS、
音频、封面与逐字稿;这些第三方会接触 IP、User-Agent 和所访问的资源。

## 二、把节目找进来

### 粘贴 RSS 地址(所有版本)

搜索框里粘贴 `http(s)` 或 RSS 地址,直接解析导入。这是最本质的一条路——
只要发布方有 RSS,余音就能订阅,不依赖任何目录服务。

### 私有订阅:需要用户名密码的源(未发版)

有些源是私有的——会员站的 WordPress、自建的有声书服务器、只给几个人听的播客。
它们同样是 RSS,但 feed 和音频都要一对用户名密码,不带就一律被拒。
现在把地址粘进来,余音会在对方要求时问一次账号密码,输对了就照常订阅、播放、下载、读逐字稿。
地址里本来就带着 `用户名:密码@` 的写法也认,但**存下来的订阅地址不会留着它们**。

- 四端一致(Android / HarmonyOS / macOS / iOS)
- **凭据只存这台设备**,不进「完整备份」、不进 OPML 导出;在应用里退订这个源,凭据同时删除。
  换台设备要重新输一次——这是故意的,口令不该跟着备份文件到处走
- 只把凭据发给**这个源自己**的域名(含它的子域),音频放在无关的第三方 CDN 上时不发——
  宁可不带,也不把口令交给与你无关的主机
- 已存的密码不对时会再问一次,并预填用户名;服务器换了密码也不用卸载重装
- 已知取舍:私有源的**封面**暂时取不到(会显示占位图);跨主机跳转、明文 `http://` 源
  按对方与网络情况处理,后者等于明文传口令,建议优先用 `https://`

### 导入推荐订阅(所有版本)

还没有心爱的节目时,也可以点「导入推荐订阅」,从官网取一份精选清单**整份导入**。
它是在线目录之外的一条可选入口。

### 分类热门榜与关键词搜索(所有版本)

19 个分类的每日热门榜(推荐 / 新闻 / 商业 / 科技 / 文化 / 知识 / 教育 / 喜剧 / 健康 /
历史 / 体育 / 美食 / 旅行 / 动漫 / 情感 / 艺术 / 音乐 / 亲子 / 影视),
磁盘缓存秒开、后台刷新;以及「单集 + 节目」两个分段并行的关键词搜索。

搜索框的提示会写清它接受三种输入:关键词、RSS 地址、视频链接。搜索结果的**来源逐条标出来** ——
单集是一行一个来源小签(B 站 / Apple),节目那一段在表头标来源;因为单集结果是两路拼起来的,
一个大标题装不下两个来源,而滚到哪里都该看得见这一条是从哪来的。

- Android(那一份包,两个分发处同一个文件):分类 chips + 横滑分页,支持下拉刷新,分类顺序可长按拖拽自定义
- macOS:安静的分类下拉菜单 + 卡片网格,工具栏刷新按钮;分类顺序可在下拉末尾「自定义分类排序…」里拖动或用箭头调整
- HarmonyOS:分类 chips + 横滑分页,支持下拉刷新,分类顺序可长按拖拽自定义;
  节目搜索结果先展示,首屏前四条以两路并发检查 RSS,
  当前网络不可访问的条目保留但不允许进入,其余长尾结果仍可直接打开

只有 HarmonyOS **不打包内置精选清单**。首次安装时的发现内容来自在线榜单;
无网且没有缓存时不会回退到 `seed_podcasts.json`。Android 自 2026-10-18 合并 flavor 起
**连大陆商店那一路也带这份清单**(以前只有自分发的 `default` 包里有,H205)。

### 搜索历史与语音搜索(1.1.0)

搜索框会记住你**最近真正发起过的**检索词(最多 20 条,新的在前,重复的提到最前)。
聚焦搜索框、还没输入时,列出这份历史:点一条直接再搜,行尾的 × 删掉这一条,
表头「清空」一键删全部(会先问一次)。输入到一半、粘贴了却没提交,都不会进历史 ——
否则里面很快会塞满半截词。

这份历史**只存在这台设备上**:它不进完整备份、不参与局域网同步、不上传给任何服务器,
换机或重装后为空。理由很简单 —— 它是"这台设备上顺手搜过什么"的快捷方式,
价值不足以承担同步协议与删除传播的成本。

搜索框右侧还有一个麦克风按钮(仅在本机离线识别可用、且当前语言受支持时出现):
**点一下开始录音,再点一下结束**,你说的话交给本机离线识别引擎转成文字,
填入搜索框并直接发起这次检索。录音只活在内存里(桌面与 iOS 端为应用临时目录),
识别完立即丢弃,不保存、不外发;麦克风权限只在你点按这个按钮时才申请。
录满 30 秒会自动放下麦克风,但按钮仍停在"录音中",由你自己点结束。

四端行为一致;鸿蒙用的是与逐字稿同一套 sherpa-onnx 引擎(独立 Worker,不与整集转写抢队列),
桌面与 iOS 用系统自带的 Speech 框架。

### 粘贴视频链接,直接听音频(1.0.6)

有些内容你只想听,不想看。把**视频页面链接**(或它的视频编号)粘进搜索框,
余音会把它变成一条普通的单集:封面、标题、时长、频道名都在,按播放就出声。
不登录、不用扫码、不跳浏览器;按关键词做单集搜索时,这类结果也会和播客单集并列出现。

- 四端一致(Android / macOS / HarmonyOS / iOS)
- **不提供下载**:视频来源的单集下载键是灰的。自动缓存照旧——听过一次就留在本机,
  下次直接从本地起播,占的空间受缓存预算约束,可在设置「清除缓存」一并删掉
- 只对付费(充电)开放的视频拿不到可播的音频:对方不给分段的音频轨、只回一段截短的混流预览。
  余音不会拿预览段顶替整集——这类视频**不会出现在搜索结果里**;万一你从历史或待播里点到一条,
  只会看到一句「这一集暂时播不了」,正在播的那一集与它的声音都不受影响(见 H232)
- 音频地址由对方按次发放、约两小时失效,所以每次播放都重新解析一次;本机只记视频编号

### 粘贴直播流地址,直接听(1.0.7)

网络电台和直播流也能当一集来听。把**音频流的地址**粘进搜索框,确认它是音频之后,
结果区会出现一条标着「直播」的条目,点一下就开始出声。

- 四端一致(Android / macOS / HarmonyOS / iOS)
- **只认真正的音频**:对方自己的响应说得清它是音频流(音频类型、HLS 播放列表、或 ICY 电台头)才放行;
  粘一个普通网页不会播出一个"假电台"
- **不装作有时间轴**:直播没有"听到哪了"这回事,所以播放页把进度条换成一行「直播中」,
  快进/快退收起、上一集/下一集置灰(仍在原位、按不动)、倍速也收起(直播是线性的);
  也不记录播放进度、不进历史、不占缓存空间
- 断流就停,不会自动换到别的内容
- 你粘的如果其实是一个**有限**的音频文件,播放器一报出时长,进度条与快进就自动回来
- 1.0.7 只支持你主动粘贴的那一条地址;直播目录与投播自 **1.0.9** 起补上,见下一节

### 直播电台:把常听的台收进来(1.0.9)

顶层多了一格「电台」,专门放**网络电台直播流**。它和「随机电台」不是一回事:
后者从播客热榜里随手抽一集自动续播,这里的每一条都是你自己收下的一路直播。

- 可以手动添加、编辑、删除电台地址;同一个地址不会重复出现
- 也可以按名称搜索公开的在线电台目录(`radio-browser.info`),搜到就直接试听或加进我的电台;
  搜索词只发给这个目录,不登录、不带任何用户标识。列表出来前会逐个确认能不能连上,
  **连不上的台不会出现在列表里**;这个确认会向结果里的每个电台地址各发一次只取响应头的请求
  (对方因此会看到你的 IP 与 User-Agent),详见隐私政策
- 搜不到或者没网时,页面仍会列出随应用打进的 16 个精选电台(新闻 / 音乐 / 谈话 / 怀旧),
  点一下就能听;精选是只读的,你加进自己列表之后改名、删除都不会动到它
- 点一行就是听这一路流,和搜索框粘贴地址走的是同一条直播路径;不记历史、不占缓存、不算收听时长,
  断流即停
- 电台清单只进「完整备份」的电台一段,**不参与局域网同步**——它是"这台设备上的快捷方式"
- **Android / 鸿蒙版自 2026-11-24 起默认只显示搜索与试听**:
  可在「设置 → 功能 → 完整直播电台」手动开启,恢复「我的电台」、热门、随包精选与
  添加 / 编辑 / 删除。完整代码、已保存的电台账本与随包清单都保留,不会因为隐藏而删除;
  macOS / iOS 保持完整形态

### 把声音投到电视 / 音箱(1.0.9)

播放页多了一个「投放」入口,把当前这一路声音交给同一 Wi-Fi 下的另一台设备:
电视、音箱、Apple TV 或 HomePod 之类。设备发现与传输都在局域网内完成,**不经过任何服务器**,
也不用登录任何账号。

- **Android** 自己找 DLNA 媒体渲染设备(电视、音箱),选中后由设备直接拉流;
  投出去之后手机先暂停(队列与进度都留着),点「停止投放」就能在手机上接着听
- **HarmonyOS** 用系统的投播组件,由系统发现并传输
- **macOS / iOS** 用系统的 AirPlay 路由选择器
- 播放页换集、停止投放时,设备那一路也会一起停,不会两边各响一份
- ⚠️ 投播已经用软件接收端(Macast,跑在电脑上)验过 Android 整条链路,但**还没有在真实的电视 / 音箱 / AirPlay 设备上跑过**;
  首次上手的失败可能来自路由、格式或网络,而不是界面

### 关掉不需要的模块(1.1.0)

设置页靠后(日志之前)多了一个「功能开关」:逐字稿、电台、投放、局域网同步四项默认全开;
Android / 鸿蒙另外多一项「完整直播电台」,默认关闭。关掉哪一项,对应的入口就收起 —— 不想要的顶层
「电台」一格会消失,播放页不再出现投放按钮,设置里的局域网同步也不再出现。Android / 鸿蒙关闭
「完整直播电台」后,电台页只保留搜索与试听,手动开启即可恢复我的电台、热门、随包精选与
添加 / 编辑 / 删除。这里的「电台」只指底栏那个直播电台页;首页右上角的随机电台与设置里的
「电台模式」不受影响。正在播的直播流会在关掉「电台」时停下;普通播客与已下载的内容不受影响。
这些开关随时可以再勾回来,代码、数据与随包资源都不会被删。

### 分享频道 / 朋友圈海报(1.0.2)

频道详情页右上角可生成一张 3:4 的水墨竖版海报,包含频道 Logo、频道名、简介和「余音 · Reverb」落款,
再交给系统分享面板,或存进相册。微信没有向第三方开放「直接发朋友圈」的接口,
所以这一步停在把图片交给你:在微信里发朋友圈时从相册选这张图即可。
卡片不带 RSS 地址,避免私有订阅源里的访问凭据随分享泄露。

### 新手引导音频(所有版本)

全新安装且没有任何使用痕迹时,发现页顶部有一张引导卡,点按播放随包内置的 30 秒音频。
它的用途是让你在**完全没有网络、还没订阅任何节目**时就能走通整条播放链路
(播放条 / 进度 / 倍速 / 后台 / 锁屏)。有任何使用痕迹后它就不再出现,且不计入历史与收听时长。

## 三、听

### 播放页

全屏播放页是横滑的多页结构:

1. **封面**——背后是会随播放流动的水墨声波
2. **节目笔记**(shownotes)
3. **逐字稿**——见下一节(有稿时才出现)

底部是进度条、快退/快进、上一集/下一集。频道名可点,跳到该频道主页
(听随机电台时尤其有用——你会想知道这是谁)。

发布方提供了**章节**的单集,进度条上方会多一行当前章节名;点开就是整张章表,
点一条直接跳到那一段。章表取过一次就留在本机,断网时照样能看能跳
(1.0.8 起四端支持)。

### 播放能力

| 能力 | 说明 |
|---|---|
| 后台与锁屏 | 退出界面、锁屏后继续播;系统媒体控制可切集 |
| 倍速 | 0.8× / 1.0× / 1.25× / 1.5× / 1.75× / 2.0×,可设默认值 |
| 快退 / 快进 | 秒数可在设置里改 |
| 睡眠定时 | 15 / 30 / 45 / 60 分钟,或「听完本集」;最后 8 秒音量线性渐弱后暂停 |
| 音频淡入 | 每次开播新节目音量柔和渐入(约 0.9 秒),不炸耳 |
| 精准续播 | 记住每集进度,重进自动定位;回跳有护栏——不会把你甩回开头,也不会漏掉结尾 |
| 已播完标记 | 自然听完自动标记并把进度归零;手动**只能往回改**,入口只有 `音阁 · 历史` 那一列(已播完的行长按 →「标记为未播完」) |
| 播放队列 | 「下一个播放」置顶 / 「加入队列」入队,可视化查看、重排、清空;点队列里的单集立即跳播(从队列摘出),节目详情页单集行与迷你播放条都有一步入队 / 队列入口;这条队列在**音阁里也占一段(「待播」)**,段里就是同一个列表(1.0.4)。**排好的队列和"正在播哪一集"都不会因为退出应用而消失**(1.0.4):重新打开时播放栏还在、进度还在、上下一集还接着原来那一列,而且已经替你装载到「按下就出声」(保持暂停,不自作主张播) |
| 播放模式 | 一颗按钮只切模式:**顺序 / 单曲循环 / 随机**,点一下走一格,图标就是当前模式。挂在**追更**页的页头、音阁「收藏 / 下载」两段分段条右端,以及**频道主页**单集数那一行右端(「待播」那一段不放:它自己就是正在排的那条队列),**每一列各记各的**(在追更设的随机不会影响收藏;没设过的列沿用你上一次的全局选择)。起播不需要专门按钮 —— 点列表里任意一集,这一整列就成为播放队列,播完一集按当前模式接下一集(**当前 Android / 鸿蒙有;macOS 代码已同构移植,但本机工具链跑不起来、尚未运行验收**) |

### 从桌面接着听(未发版)

四端都在桌面上放了一张「继续收听」卡片(Android 桌面小部件、鸿蒙服务卡片、macOS 通知中心 /
桌面小组件、iOS 主屏小组件):封面、标题、频道名、进度条与「已听 / 总时长」。
小 / 中 / 大三种尺寸,窄条与方形各有独立排法;没有可继续的内容时,卡片显示「挑一集开始听」。

卡片上有播放控制:方形小卡把播放键压在封面上,其余尺寸给一行「上一集 / 播放暂停 / 下一集」,
按下去只在后台改变播放状态、不拉起界面(iOS 17 / macOS 14 起;macOS 13 只有卡片与进度)。
点一下打开播放页并**装载成暂停态**——从上次的位置接着听,但不会自己出声;
鸿蒙上应用没在运行也一样,点卡片直接落在播放页,不会先看到首页再跳过去。
这样进来的播放页,**按返回就是退出应用**——它下面没有你自己建的页面栈,不必先退一次首页;
应用内点开的播放页照旧返回首页。
鸿蒙的中 / 大卡片上另有一行「上一集 / 播放暂停 / 下一集」,方形小卡把播放键压在封面上:
按这些键**只在后台改变播放状态,不把应用拉到前台**;卡片上的图标会跟着翻面。
卡片正文不再带「继续收听」这样的一行小字 —— 卡片本身就在说这件事,标题直接从顶部排。
挑选口径与发现页的「继续收听」横条一致:未播完、进度在 10 秒到 95% 之间、最新在前;直播没有进度,不进卡片。
卡片跟着 App 更新:换集、暂停、拖动进度都会推一次;播放中的进度刷新,鸿蒙约 5 秒一次
(进度条按 0.1% 步进),Android 为 20 秒一次。
鸿蒙的上一集 / 下一集会沿着当前节目那一列切,切回来还停在原来的位置。
按卡片时整卡轻微回弹是系统对**所有**这类卡片统一的按压效果,应用这边关不掉;
但按键不会再把封面重新加载一遍,内容也不会因此重排。

### 锁屏上也在播(iOS,未发版)

iPhone 上开始播放之后,锁屏与灵动岛会常驻一张播放卡:集名、频道名、已听 / 剩余时间,
以及「上一集 / 播放暂停 / 下一集」。**它只在这台设备真的在播时出现** —— 暂停时留着(方便就地续播),
15 分钟没有继续就撤下;换集先换卡,不叠两张。进度由系统自己走,应用不会为了它每秒钟醒一次;
直播流显示「直播」而不画进度条。

### 水墨声波

播放时封面背后的墨纹会流动。**Android 版(那一份包,两个分发处都有)**可以在设置里开「真实频谱」,
让墨纹跟随实际音量起伏——这需要麦克风权限,音频**只在本机做频谱计算,不录制、不保存、不外发**,
默认关闭。macOS 与鸿蒙没有等价的系统能力,走纯程序化墨纹。

## 四、逐字稿(跟读)

播放页横滑到第三页,这一集的文字逐句显示,**跟着播放进度高亮**,点一句就跳到那一刻。
每单集 × 每语言一份缓存,再进来秒开。

**文字从哪来,各端不同**——这是可用的系统能力(与曾经的渠道口径)决定的:

| | 发布方提供的逐字稿 | 本机转写 |
|---|---|---|
| **macOS** | 有(1.0.6 起与 Android 同一条解析与下载路径) | 有(系统 `SpeechAnalyzer`,**词级时间**;要 macOS 26) |
| **iOS** | 有(与 macOS 共用解析/下载层) | 有(系统 `SpeechAnalyzer`,词级时间;**要 iOS 26**) |
| **Android(唯一那份包)** | 有 | 有(**sherpa-onnx + SenseVoiceSmall**,token 级时间;只认 zh / en / ja / ko / yue) |
| **HarmonyOS** | 有 | 有(同一套 **sherpa-onnx + SenseVoiceSmall**,token 级时间;语言与限制同 Android) |

Android 那一行以前是两行:「自分发的 `default` 有本机转写 / 大陆商店 `store` 没有」。
**2026-10-18 合并后只剩一份包,商店那一路也带上引擎与模型了**(H205)。

**1.0.8 换了本机引擎**(whisper.cpp → sherpa-onnx + SenseVoiceSmall int8):中文明显更准、
自带标点与逐字时间,代价是安装包从约 65 MB 涨到约 270 MB
(鸿蒙同样从约 1 MB 涨到约 271 MB)。**五种语言之外(fr / es 等)
没有本机转写**——界面在入口处就说明原因,官方逐字稿不受影响。为什么换、换成了什么、
实测数字见 `docs/research/2026-11-11-offline-asr-engine.md`。

没有本机转写的界面(Android 与鸿蒙上的 fr / es 界面)里,**只有发布方给了逐字稿的单集才会出现第三页**——不给你一个点了没用的空页。

一个现实提醒:**中文播客基本没有官方逐字稿**(实测 15 个中文 feed,`podcast:transcript` 零命中);
英文播客有一些,尤其自动生成稿的托管商。所以对中文内容,真正管用的是带本机转写的那一端。

### 逐字高亮(设置项)

打开时**逐字点亮**而不是整句一起亮。它需要稿件自带**词级时间**:
JSON 格式的官方稿通常有,SRT / VTT 只有句级时间,那时自动退化成整句高亮。
Android 那份包的本机转写也有词级时间,**且不额外增加转写耗时**。

### 全文搜索与导出(1.0.8,三端)

稿子长了,靠"往下翻找那句话"是不现实的。逐字稿页顶部有两个入口:

- **搜索**:输入一个词,命中处**贴底色**,右边显示「第几处 / 共几处」;
  前后箭头逐处跳,**跳过去的同时把音频定位到那一句** —— 找到一句话,就能从那句接着听。
  没有命中时写明「没有匹配」,箭头置灰。搜索期间**跟读不再自动滚动**,
  否则你刚翻到的地方会被播放进度拽回去。
- **导出**:把整篇稿子存成文件,走系统分享面板,可以发给自己、存进笔记或附到邮件里。
  两种格式:**纯文本**(`.txt`)与 **Markdown**(`.md`);每句前面带 `[12:03]` 这样的时间戳,
  方便日后按时间找回原处。文件名与分享卡片上的标题就是**这一集的名字**。

同一集在两端导出的文件内容一致(排版、时间戳位数、空行都一致),可以互相 diff。
鸿蒙这一端只对**发布方提供逐字稿**的单集有第三页,所以搜索与导出也跟着只在这些单集上出现。

## 五、追更与音阁

底部三格:**发现 / 追更 / 音阁**(Android 与鸿蒙;macOS 仍是两格,聚合还在音阁那一段里)。

- **追更** 是跨全部订阅聚合的**全部单集**:并发拉取、去重、按发布时间倒序,一直往下翻就是翻你订阅过
  的每一集;本地留最近 300 条用于秒开,进页与下拉再做增量刷新。
  它原先是音阁里的一段(那时叫「最新」),2026-10-08 提到顶层独立成一格 —— 因为它是每天打开
  App 要看的第一眼,不该要靠横滑才够得着;**2026-10-10 从"只看新的"改成"整栏都能翻"**(此前每源只留
  最新 12 集、整栏封顶 100 条)。页头那颗按钮给**这一列**单独设播放模式。
- **音阁** 六段:**订阅 / 收藏 / 下载 / 待播 / 历史 / 批注**。
- **点封面直达频道**(自 1.0.5,Android 与鸿蒙):列表里和迷你播放条上的头像/封面单独可点,
  点进去的是**这一集所属的频道页**;行的其余部分照旧是"播这一集",两套语义不打架。
  频道页里这一门是关的 —— 已经在这档里,再点等于往回退的路上压一份自己。**macOS 未做。**
- **多选批量加入待播**(同样自 1.0.5,Android 与鸿蒙):**追更 / 收藏 / 下载 / 历史 / 频道页**五栏长按任一单集,
  菜单里选「多选」就进入勾选态,底部浮出一条(已选 N / 全选 / 加入待播 / 退出)。
  勾选态下点行是**勾选**不是播放,行尾那排操作图标会先收起来。
  「待播」那一段自己不参与多选 —— 它本身就是那条队列。
  提示说的是**真的新增了几集**:已在待播里的会被去重,一条都没新增时那句是「所选都已在待播里」。**macOS 未做。**
- **长按菜单不再提供「标记为已播完」这一颗**(自 2026-10-17 两端一致,所有单集列表一起收口):
  它的作用域是「这一集在收听历史里」——各端的 `markPlayed` 都是"找到那条历史再改它的 played",
  找不到就什么都不发生。而浏览列(发现首屏 / 追更 / 收藏 / 下载 / 搜索结果 / 频道页)列的恰恰以
  **没播过的集**为主,所以对多数行它是**静默空操作**,对少数行又只剩标题压暗、且当页没有回程。
  **反向那颗留在 `音阁 · 历史`**,而且只给已播完的那些行 —— 因为发现页「继续收听」横条上那句
  「标记已播完」改的就是同一份状态,不在历史页给回程就变成不可撤销。**macOS 仍无条件带正向那颗**,
  是三端里唯一没收口的一端。**待播那一列本来就没有这颗,也没加**:它自己就是那条队列,
  而且队列行不显示已播状态。
- **待播** 就是你排好的那条播放队列:行内上移 / 下移 / 移除,这一段右端可以一键清空
  (清空**先弹确认** —— 队列里的顺序是用户自己排的,一刀切下去没有找回办法)。
  它和「打开迷你条队列入口」进来的那一页是**同一个列表**(同一套行内操作),不是两套实现。
- **下载** 的单集播放时优先用本地文件;Android / 鸿蒙都有「仅在 Wi-Fi 下载」开关(默认开 = 不允许蜂窝),
  但**两端的判据不等价**:Android 看这条链路**是否计费**(`isActiveNetworkMetered`,所以限量热点也拦),
  鸿蒙这台设备连着 Wi-Fi 也不上报计费信号,只能看**是不是蜂窝链路**(所以限量热点会放行)。
  取不到网络信息时两端都放行,不误拦。为什么不能做成一致,见 `TROUBLESHOOTING` H166。
- **播放缓存** 是另一件事,和下载分开存在:某一集**第一次在线播放**时,后台顺手把整集取回本机,
  下次再点它直接从本地文件起播、不再联网(自 1.0.5,Android 与鸿蒙;macOS 自 1.0.6 起同一条口径)。
  它不需要你点名,也**没有进度条** —— 它的产品语义是"听过一次就别忘了",不是"帮你存一份"。
  所以下面三件事是刻意的:
  ① 存在**单独的目录与单独的账本**里,和下载互不 overlap,预算淘汰永远挤不掉你点名下载的那一份;
  ② 有**字节预算**(300 MB,大约最近 6–8 集),超出按"最久没听的先删"—— 无上限等于把你的手机当网盘;
  ③ **电台不缓存**(直播流没有"整集"可存,而且每台几十 MB 会把预算刷爆)。
  这一层同样受「仅在 Wi-Fi 下载」那道闸门管,副标题因此写的是"下载与缓存":App 替你做的流量决定,
  比你自己点的更不该在蜂窝上跑几十 MB。**桌面端没有这道闸门**(Mac 没有蜂窝基带),其余口径与手机同。
- **断网也能浏览**:已经加载过的榜单与频道列表(文字)此前就有磁盘缓存,**封面图片自 1.0.5 起也落盘**
  (Android 复用图片库的磁盘缓存,鸿蒙与 macOS 本端没有带缓存的图片库,所以各自写了一层,预算 20 MB)。
  补这一层的直接原因是:鸿蒙此前一张图都没存,断网进发现页会看到整屏空白格。
- **历史** 支持一键清空(同样**先弹确认**);未播完的会出现在发现页的「继续收听」横条里。横条上的某一条可以
  长按「标记已播完」把它挪走 —— 那是**从首屏让位**,不是删记录:条目连同进度留在历史里,
  在历史里「标记未播完」即可让它回来。

频道详情页**离线优先**:先出上次解析结果(秒开,不从加载态起步),再后台刷新;
刷新失败沿用缓存并标注「离线内容 · 上次更新 …」。也可以**手动刷新**:
Android / 鸿蒙在详情页下拉,macOS 点详情页工具栏的刷新按钮 —— 强制重新拉取,
且不会清空已经展示的内容。HarmonyOS 的 RSS 请求有可销毁的硬截止,
无缓存且当前网络无法访问时会在有限时间内结束并给出明确提示,不会重复请求或永久转圈。

## 六、让听过的留下痕迹

这一组是余音的性格所在——它们都不联网、不外发,只是帮你把「听」变成可回看的东西。

### 收听时长

按频道累计**你真正听过的内容时长**:反复听会累加,快进跳过与暂停不计入。
频道主页头部显示「已收听 X 小时 Y 分」,音阁里有一页按时长从多到少排序、带横条对比。

**多设备不会算错**:时长按设备分账存储,展示值是各设备之和,备份合并按设备取最大值。
所以——同一份备份重复恢复不会翻倍,换机恢复会把两台的时长正确汇总,
各设备自己新听的也不会被抹掉。

### 听觉印记与足迹

为一集盖一枚 **3×3 水墨情绪印章**(喜 / 暖 / 燃 / 惊 / 思 / 悟 / 悲 / 怒 / 疲),
再点同一枚即取消。所有印章汇成一张**听觉足迹**海报,可导出。

### 批注 · 写下这一秒

听到某一句被触动,就像读书时划一道线那样把那一刻记下来:播放页上有一颗**写批注**的入口
(Android 与鸿蒙在「更多」菜单里,macOS 没有那个菜单,它是动作行上的一支笔),
弹窗顶上显示的是**按下那一刻**冻结的时间,正文写一句话。
所有批注在音阁「批注」段汇成一条**跨单集的时间线**,点任意一条就回到那一秒接着听。

与印记的分别:印记记的是**心境**(一集一枚章),批注记的是**一句话和它所在的那一秒**
(一集可以有很多条)。

> **三端 2026-10-01 都已实现,但当时都还没跑起来看过**(Android / 鸿蒙只过了编译,
> macOS 只过了类型检查)。iOS 2026-11-02 加入,同样只过了编译门、尚未实跑。
> 各端共用同一套数据格式(`notes.json`,毫秒位置 + 整条单集快照),批注随备份跨端迁移。

### 剪藏此刻

把当下这一句做成卡片(封面 + 标题 + 时间点 + 水墨波纹),系统分享或保存到相册。

## 七、外观与语言

- **液态玻璃导航**(Android):底部导航(发现 / 追更 / 音阁)与顶部分类条为悬浮玻璃,胶囊随页面滑动实时贴合。
  1.0.5 起这一端也做了同一件事:**向下滚动时迷你播放条收进底栏那一行,并分成两个物体**——左端一颗独立的
  小圆球(球上是当前这一格的图标)+ 播放条自己收成一条胶囊(块高与那一行等高、有自己的不透明底),
  中间留一道缝,而玻璃栏整条在这一态**淡到看不见**;于是那一行归播放条与那颗球,**三个 tab 点不动**,

- **鸿蒙端 1.0.5 起底部改用系统提供的悬浮页签**(整条悬浮在内容之上、左右各留边、背景是系统材质,

  不支持"按住横向拖动切格"。上面那条"播放条收进底栏"本端先做,形态与 Android 同一套语义
  (数值各自按本端惯例,不互相对齐)
- **四套主题**:跟随系统 / 浅色 · 宣纸 / 深色 · 水墨 / 纯白
- **四组配色**:青瓷 / 黛蓝 / 绯红 / 竹青
- **四档字号**
- **五种语言**:简体中文 / 繁體中文 / English / Français / Español

界面语言可在应用内单独切换,不必改系统语言。

## 八、数据是你的

- **完整备份与恢复**:订阅、下载记录、历史、印记、**批注**、设置、收听时长(可单独勾选分区),用于换机
- **局域网同步(1.0.8,四端)**:两台设备在同一 Wi-Fi 下互相发现(或手动输入地址),核对六位配对码后把订阅、收藏、印记、批注、历史与收听统计合并成并集;只在打开页面时监听与传输,不经过任何服务器。**删除也会同步**:一台设备上退订、取消收藏、删印记或删批注,对端下次同步时也会删掉(删除记录保留 90 天);本地重新添加同一项会撤销删除。已知边界:如果对端在同步前刚刚重新添加,这一次仍会被删掉 —— 订阅与收藏没有"最后修改时间",证明不了先后
- **播放进度交接(1.0.8,四端之间的同一套)**:同步完成后,只要两台设备都停在这个页面,正在播放的一方会每秒一次把「哪一集、播到哪、是否在播」告诉对方;另一台会显示「另一台设备正在播放 …」,并给出一个「在此设备继续」——**点了才接**,先让播放方暂停、拿到它暂停时的准确位置,再按网络往返补上这半程的时间,接着播。它不会自动接管,也不会在后台自动接力(关掉页面连接就断);直播流不参与交接
- **系统级备份(自 1.0.2)**:Android 与鸿蒙向操作系统声明了数据白名单,你在系统里开启备份后,由**操作系统本身**把订阅、收藏、历史、下载记录(仅链接)、印记、收听统计和设置备份到**你自己的**云账号(Google/厂商云/厂商云)或换机直连到新设备;应用没有任何参与上传的代码,开发者接触不到备份。音频、逐字稿与缓存文件(播放缓存、封面图)不占备份,换机后重新下载或重新听即可。它是「备份/恢复」而非实时同步
  - ⚠️ **批注从 1.0.4 起才进这份白名单**(2026-10-01 加进三端源码,而在架版本在它之前就出了):
    **已解包实测**在架鸿蒙 1.0.3 的 `backup_config.json` 只有 **8 项、不含 `notes.json`**
    (`unzip harmony/dist/reverb.app` → 再解 `entry-default.hap` → `resources/base/profile/backup_config.json`)。
    换句话说「系统备份里有批注」这句话**对 1.0.4 及以后成立,对在架版本不成立** ——
    上一版这句没带版本限定,读者会以为在架的那版已经把批注备走了
- **OPML 导入导出**:标准格式,可与其它播客应用互通
- **清除**:缓存、下载、历史各自独立清除,都有二次确认,设置页各自显示当前占用。**「清除缓存」不会动你下载的单集**
  —— 两条是两套文件、两个入口;自 1.0.5 起缓存那一格计的是榜单 + 频道列表 + 逐字稿 + 播放缓存 + 封面图 五件,
  清完当场重新统计

恢复备份的合并规则是**保守的**:历史按更新时间取新(旧备份不会让当前进度倒退),
收听时长按设备取最大值(不会重复累加)。

## 九、隐私

完整政策见 `PRIVACY.md` 与官网。要点:

- 没有开发者后端、账号、广告、统计、归因、第三方登录/推送、崩溃上报或跨应用追踪
- 订阅、历史、收藏、下载、收听统计、设置、安装随机标识与运行日志在本机处理,不向开发者自动上传
- 系统级备份的数据只进入**你自己的**系统云账号,由操作系统执行,开关与删除都在系统设置;详见 `PRIVACY.md`「关于系统级备份」
- **局域网同步**只在同一 Wi-Fi 内、由你主动配对的两台设备之间直传,密钥临时协商、配对码两端人眼核对,不经过任何服务器;它在局域网内广播设备名与一小段随机标识,关闭页面即停止。**播放交接**在同一页面、同一条加密连接里发生:只把当前这一集的标题、封面、音频地址与播到哪儿告诉对方,不回传任何其他数据;详见 `PRIVACY.md`「关于局域网同步」
- 联网会把搜索词、地区或分类发给 Apple / fyyd.de / gpodder.net 等公开目录,并直连发布方或托管方的 RSS / 音频 / 封面 / 逐字稿;第三方会接触 IP、User-Agent 与所访问资源
- **首次启动有隐私同意门**:同意之前,任何会联网或读系统网络信息的组件**一个都不装配**
- 本机转写(Android 那份包 / 鸿蒙 / macOS / iOS)全程在设备上完成,**音频不上传、不出设备**
- **应用内更新(Android 那份包自 1.0.5、macOS 自 1.0.6;设置页「检查更新」自 1.0.6)**:冷启动时向 GitHub 的**公开发布页**问一次「最新版是哪个」
  (macOS 主路读发布流,不占接口配额;Android 读发布页接口以比对发布物字节,限流或失败时退回发布流),
  请求只含本应用自己的公开仓库地址,不含账号、标识符、订阅列表或收听内容;确实有新版才下载。
  **Android** 默认只在 Wi-Fi 下自动下载(按流量计费的网络先问),装那一步交给**系统安装器**;
  下载在前台服务里进行、进度显示在通知栏,进度弹窗可以收起(点「后台下载」或点窗外),
  收起后可以继续用应用或锁屏,下载不会中断;
  **macOS** 下载的是磁盘映像,下载完由你自己打开安装,应用不会自行安装;关掉设置窗或退到后台,
  下载仍会继续。
  两端都支持**断点续传**:下载中断后,下一次检查或应用重新启动会从断点接着下,不必整包重来。
  设置页另有一条**「检查更新」**,点它走的是同一次询问(不受「这个版本你之前说过以后再说」的限制),
  结果直接写在那一行下面,不弹额外的窗。
  Android 的版本判据除了比版本名,还比**发布物的字节**:同版本号重新出包(资产摘要与本机这份不同)也算一次更新 ——
  这一条是为了堵「一天里重打三次、版本号没动、老设备永远收不到」那个缺口(见 `TROUBLESHOOTING.md` H234)。
  **macOS 只按版本名判新旧**:发布的是磁盘映像、本机装的是 `.app`,两者字节不可比,所以同版本重出包不会主动提示。
  ⚠️ **合并 flavor 之后,交去大陆商店的也是这一份包 —— 这个接口与「安装未知应用」权限随之进入商店包**
  (可解包验证;合并前 `store` 那份压根没有,H205)。市场侧的升级仍由应用市场负责,两套并存。

关于麦克风:**Android 那份包**的可选功能「真实频谱」会用到,默认关闭、
系统单独征求同意、音频只做本机频谱计算。**它随包带 `RECORD_AUDIO` 权限**(合并前商店那份没有,
解包 grep 的期望值因此已翻转,H205)。macOS 与鸿蒙没有对应能力,不申请麦克风。

## 渠道差异(为什么各端仍不完全一样)

大陆分发受登记申报口径约束:现有申报口径是「用户自行添加 RSS 源」的纯工具;
「内置内容目录 / 分类浏览 / 内容推荐」可能被要求提供相应内容分发许可资质,
个人主体无法取得。此前因此移除过商店渠道目录。当前决定是**按完整目录能力发行,
若合规要求再降级**(见 H70 与 H205),并不代表上述合规风险已经消失。

**2026-10-18:Android 不再打两种包。** 原先这张表的左右两栏合并成一栏 —— 那份包同时交
大陆应用市场与 GitHub Releases,所以「商店版有没有某功能」这个问题从此与「自分发版」是同一个答案。

| | Android(唯一那份) | macOS | HarmonyOS |
|---|---|---|---|
| 分类热门榜 / 关键词搜索 / 随机与情境电台 / 直播电台 | 有 | 有 | 有 |
| 投播(Android 自研 DLNA;Apple 走 AirPlay;鸿蒙走系统投播) | 有 | 有 | 有 |
| 内置精选清单 | 有 | 有 | **无**(不打包种子文件) |

| 真实频谱(麦克风) | 有(可选,默认关) | **无**(平台没有等价能力) | **无**(同) |

**iOS(2026-11-02 起)走 TestFlight**,不涉及渠道差异;功能上与 macOS 共用数据 / 播放层,
差别只有:没有应用内更新(TestFlight / App Store 负责),以及平台没有真实频谱。
**「仅 Wi-Fi 下载」闸门 2026-11-04 已补齐**,并覆盖下载、首播落缓存与转录前下整集三条路径;
订阅更新提醒用系统后台任务每 6 小时检查一次,与手机两端同叫法、同开关。
**iOS 的小组件要 App Group 才能读到 App 的状态**:模拟器上用 ad-hoc 安装可以直接写通;
真机 / TestFlight 上这需要付费 Apple Developer Program,免费 Personal Team 的真机签名下卡片只能显示空态
(App 日志会明说一句)。卡片上的播放键由 `AudioPlaybackIntent` 交回 App 执行,只在后台改播放态、
不打开界面;未同意隐私时动作被丢弃,与主界面启动门同一条(iOS 17 / macOS 14 起)。

**「界面上有」不等于「包里真的有」**——这句话在合并后依然适用于**降级档**:三个编译期常量
(`CATALOG` / `SPECTRUM` / `AsrFactory.HAS_ENGINE`)任一降到 `false`,就要按解包 grep 重新验一遍;
而合并前那条「商店包不得含语音模型、native 库与 `RECORD_AUDIO`」的期望值**已经翻转**,
现在那几项在非 0 一侧(实测数字与判据见 H205,命令见 `AGENTS.md` 硬规矩 1;
1.0.8 换引擎后的现读数见 `docs/ARCHITECTURE.md` 第六节末)。
鸿蒙没有 DCE,那端的"真的没有"只能靠把代码移出编译树(见 `harmony/shelved/`)。
