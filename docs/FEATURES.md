# 余音 · Reverb 功能清单

> 一款轻量的多端播客客户端。**纯客户端、零开发者后端、零 API Key、不接广告、统计等数据上报 SDK,打开即用。**
> 现已提供 **Android**(Kotlin / Jetpack Compose)、**macOS**(Swift / SwiftUI)、**鸿蒙**(ArkTS / ArkUI,HarmonyOS NEXT)、**iOS**(Swift / SwiftUI,TestFlight)四个原生版本。
> 本文档按功能域汇总当前全部能力,供产品与开发对齐。凡各端行为不同或为单端独有,均在「平台差异/说明」注明。
>
> **鸿蒙端已具备**:取源与 RSS 解析、分类热门榜、节目 + 单集关键词搜索、RSS 导入、频道详情与订阅、
> 随机 / 情境电台、**顶层四入口(发现 / 电台 / 追更 / 音阁)**、音阁六分段(订阅/收藏/下载/待播/历史/批注)、播放页 + 后台播放 + 进度续播 + 系统媒体会话与锁屏控制、
> 下载离线、**播放缓存(播过的整集自动落本机,下次本地起播)**、播放队列、收听时长(按设备分账)、听觉印记与足迹画廊、
> 剪藏此刻(存入相册)、设置(分区与条目已对齐 Android:内容 / 外观 / 播放 / 提醒 / 存储 / 备份 / 日志 / 关于)。
> 鸿蒙端还具备:**备份恢复 / OPML 导入导出、订阅更新提醒(周期检查 + 本地通知)、
> 仅 Wi-Fi 下载(1.0.5 起同一道闸门也管自动缓存)、清除缓存 / 清除下载 / 清空历史(均带二次确认;
> 清除缓存的范围见第十节「清理」一行,**与下载是两个目录、两本账、两个入口**),
> 日志四行(分享 / 发到开发者邮箱 / 导出 / 清空,与 Android 同序同条目;2026-10-06 补齐邮件行,
> 分享同时从"内联文本"改成"文件附件"),
> 关于与开源许可页、版本号**,界面文案完整外置(5 语言:简中 / 英 / 法 / 西 / 繁中;
> 键数不写在这里 —— 它每加一行文案就变,写了必漂)。
> **「完整外置」的边界(2026-10-08 补,此前这句是夸大其词)**:走资源的是**换语种要变**的那些 ——
> 许可页与「数据来源」那四条中文说明到这一天才真正进资源(此前是代码字面量,所以法/西界面上混着中文);
> 而 `OkHttp` / `fyyd.de` / `AVPlayer` 这类**专有名词与模块名**五套同形,**故意留在代码里**。
> 还有一条渠道侧的历史:合并前 Android 商店渠道把「离线识别」那两条许可条目**覆盖成空串** ——
> 代码那一支靠编译期常量删得掉,`resources.arsc` 删不掉,所以资源必须另盖一层(验收方式仍是解包 grep,见 H161)。
> **2026-10-18 合并 flavor 之后这层覆盖没了**(只有一份资源,那两条恒显示,H205);
> 但它留下了一个通用结论:**「代码里删掉了」不等于「包里看不见」**,`resources.arsc` 那一侧要单独 grep。
>
> 鸿蒙端的**图标体系**用系统 Symbol 字体(`SymbolGlyph`)与 Android 的 Material Rounded 逐个对应
> —— `sys.media.*` 仅 66 个图标、缺齿轮/柱状图/宫格/心形/月亮/下载等,不足以对齐。
> 鸿蒙端还具备:**逐字稿(读发布方在 RSS 里提供的稿;没稿时用内置的
> sherpa-onnx + SenseVoiceSmall 本机识别,语言与限制同 Android;1.0.8 起带全文搜索与导出)**。
> 系统 Core Speech Kit 那条路已弃用(离线档是给短语音输入设计的,实测质量不够用,见 H62),
> 1.0.8 换成与 Android 同一套引擎并过 Mate 60 真机验收,`Features.LOCAL_ASR = true`。
> 鸿蒙端**尚未包含**:真实频谱(鸿蒙无等价系统混音抓取,按 macOS 走纯程序化墨纹)。
> 实现与读数见 `TRANSCRIPT.md` 第三节。

> **iOS 端(2026-11-02 新增,分发走 TestFlight)**:数据与播放层**直接编译 macOS 的同一份源码**
> (`macos/Sources/Reverb/{Data,Playback}`),所以**数据口径与播放行为与 macOS 一致**;界面按触屏重写,
> 交互形态与列表操作按手机端习惯单独实现。
> **已具备**:五格(发现 / 电台 / 追更 / 音阁 / 设置)、分类热门榜与关键词检索、频道详情与订阅、
> 分类排序、播放页 + 后台播放 + 锁屏遥控、倍速 / 快进快退 / 睡眠定时 / 播放模式 / 自动续播、单集下载、
> 逐字稿(iOS 26 本机离线转写 + 发布方稿,1.0.8 起带全文搜索与导出)、随机 / 情境电台、B 站视频与直播流、
> 直播电台(自建电台账本 + 在线目录检索)与 AirPlay 投播、
> 收藏 / 下载 / 待播 / 历史 / 批注、听觉印记、收听时长、备份 / OPML、**局域网同步**、隐私同意门、四套主题与五语种;
> **2026-11-04 补齐手机端那批**:仅 Wi-Fi 下载闸门(三条大流量路径同一判据)、
> 朋友圈海报 / 剪藏海报 / 多选批量加入待播、订阅更新提醒(后台巡检 + 本地通知)、

## 渠道差异(重要)

**2026-10-18:Android 的 `default` / `store` 两个 flavor 合并成唯一一份包**(H205)。
所以这一节从此只有两种口径 —— **Android 一份包**(功能全开,同时交大陆应用市场与 GitHub Releases)
**+ 鸿蒙商店包**。原先"同一份代码打两种包"这件事在 Android 侧结束了,隔离手段变成三个
可降级的编译期常量(见本节末)。

功能范围差异的起因仍是大陆分发合规口径:「内置内容目录 / 分类浏览 / 内容推荐」可能被判定为
提供视听节目服务,需相应内容分发许可资质(个人主体拿不到);而「用户自行添加 RSS 源」的纯工具不需要。
此前据此移除过商店渠道的内容目录(H67/H70)。当前决定是**按完整版目录能力发行,若合规要求再降级**。

此前本表写成「默认渠道无」是错的 —— 而这条影响的不只是文档:同意页正文必须把麦克风权限那一条
如实说明(见 `privacy_consent_mic`;它原先分渠道、国内渠道为空串,合并后只有一份,那一条**恒显示**)。

⚠️ **关于页的自述在 Android 从此只有一份文件**:合并前 `app/src/store/res` 里另有一份**覆盖**
(flavor 是覆盖不是继承 ⇒ 同一句要改两处、五语各两份 = 10 份文件),2026-10-10 就漏过一整轮,
记在 **H169**。**合并把那两份并成一份**(`src/main/res`,五语各 402 键,用 `grep -c '<string name='` 现算)—— 那份覆盖没了,
所以"按 5 份去数"从此是对的;但**别把它当成从来如此**,H169 的教训在鸿蒙与 macOS 上同样成立。

**当前开关状态**:Android `BuildConfig.CATALOG` / `BuildConfig.SPECTRUM`(`app/build.gradle` 的
`defaultConfig`,不再是 flavor)、`AsrFactory.HAS_ENGINE` 三个全为 `true`;鸿蒙 `Features.CATALOG`
`true`、`Features.LOCAL_ASR` `true`(1.0.8 起)。若合规要求回退,把对应常量降到 `false` 就是那条降级档 ——
但**降 `HAS_ENGINE` 不会把 239 MB 的 SenseVoice 模型与两个 `.so`(共约 26.9 MB)从包里删掉**
(R8 删不掉 assets 与 native 库,硬规矩 3),那一步要把文件本身移出构建树。**鸿蒙没有 DCE**,关闭布尔值仍会把两支都编进包;
降级时必须把目录实现移出 `Sources.ets` 所在的编译树。
无论恢复还是移除,都要解包 grep 验证,并同步本表(合并那一轮的判据与实测数字见 H205)。

## 信息架构(IA)

顶层有四个入口:**发现** / **电台** / **追更** / **音阁**(iOS 多一格「设置」,见下表;macOS 为工具栏四格分段)。「电台」是 1.0.9 新增的顶层页:管理自己的直播电台、按关键词检索公开在线电台目录,与发现页粘地址起播共用同一条直播播放路径。2026-10-08 把原先音阁第二段的「最新(收件箱)」提升成底部那一格并改名**追更** —— 原先内容是"全部订阅频道的新单集",是每天打开 App 要看的第一眼,埋在六个分段里要靠横滑才够得着;**2026-10-10 再去掉截断,变成全部订阅频道的全部单集**(见第五节)。音阁里剩下六段:**订阅 / 收藏 / 下载 / 待播 / 历史 / 批注**;新进来的那一段 **待播** 就是播放队列,与独立队列页**共用同一个 body**(`QueueBody`)—— 段里那颗「清空」挂在分段条右端,独立页挂在标题栏,行内操作只有一套。播放页、设置、听觉足迹为独立全屏/独立窗口。

> macOS 1.0.9 起与手机端对齐为四格分段(发现 / 电台 / 追更 / 音阁,`RootView.swift` 的 `Section`),音阁保留六段(含「最新」、无「待播」);**「最新」的截断仍是旧的每源 12 集 / 全局 100 条**(`InboxStore.swift` 的 `perFeedCap` / `maxCount`),即在 2026-10-10 之后这一端的「最新」与两端**不是同一份列表**。这一段不是本轮改动引入的;运行验收仍固定在另一台机器(见本文末与 ROADMAP 三-A)。
> ⚠️ 底部栏从 2 槽变 3 槽:**命中带按整栏均分、内容带按内收常量走**,算术上点不偏,但透镜/药丸的观感与窄机型**只能真机重验**(两端几何已改成按槽数的通式)。

> (移进 `harmony/shelved/`),命中判定交回框架,本端不再有"槽数通式"这回事。

### 投播(1.0.9,四端)

播放页(以及 Apple 两端的电台页)多一个「投放」入口,把**当前这一路声音**交给同一 Wi-Fi 下的电视 / 音箱。各端实现不同,但口径一致:**本应用不自建服务、不经过任何服务器,设备与流地址只在局域网内传递**。

| 端 | 实现 | 状态与判据 |
|---|---|---|
| Android | **自研 DLNA**,不接任何三方库。`SsdpDiscovery` 向 `239.255.255.250:1900` 发 `M-SEARCH`(ST `urn:schemas-upnp-org:device:MediaRenderer:1`),持 `MulticastLock` 收响应 → 取设备描述 XML → 找 AVTransport 的 `controlURL`;`DlnaClient` 发 SOAP 1.1 的 `SetAVTransportURI` / `Play` / `Pause` / `Stop` 四个动作,直播用 `audioBroadcast`、点播用 `musicTrack` 的 DIDL-Lite,`protocolInfo` 用通配以放行 HLS。投播成功**本机暂停**(队列与位置保留),换集或停止投放时同步停掉电视那一路。状态机在应用级 `CastController` 里,弹层关掉不影响投放 | **单测 8 条**(SSDP 报文、设备描述解析、SOAP 转义、DIDL 两种形状、UPnP 错误识别)。设备描述改用 DOM 解析:JVM 单测里 `XmlPullParserFactory` 是 android.jar 的 stub,会把解析静默打回 null。**未接真机、未接任何真实渲染设备**(本轮屏幕锁定,无法点按;仓库内没有可用的 DLNA 电视夹具)。Android 17 起首次扫描会由系统询问「本地网络」权限(ACCESS_LOCAL_NETWORK) |
| HarmonyOS | 系统组件 `AVCastPicker`,挂在播放页标题栏;它复用本应用已有的音频 AVSession,由系统完成设备发现与传输。**本端不自己扫网、不加新权限、不接三方 SDK** | 已过 `assembleHap` 与 69 条单测;**未在真机点开、未接真实接收端** |
| macOS / iOS | 系统 `AVRoutePickerView` 的 SwiftUI 包装(`RoutePickerView.swift`,两端各一份),挂在播放页;桌面端电台页工具栏也有一枚。路由由系统 AirPlay 负责,音频仍走本端 `AVPlayer` | 两端编译门已过、共享层单测全绿;**未在真机 / 模拟器上点开路由面板,未接真实 AirPlay 设备** |

> ⚠️ 本轮投播的**验收边界**:Android 有纯逻辑单测与 release 编译,鸿蒙与 Apple 只到编译门;四端都**没有**在真实电视 / 音箱上跑过一条完整链路。这条要在下一次有屏幕、有设备时补(判据:设备出现在列表 → 点投放 → 电视出声 → 本机暂停 → 点停止 → 本机可续播)。

  Basic 头的字符集按 RFC 7617 先发 ISO-8859-1,401 且 `encodingDiffers` 时再发 UTF-8;
  feed 请求会重试,音频 / 下载 / 官方逐字稿只在第一次请求时按内容选编码(不可重试的调用点)。
  **四条已知边界**:①封面图请求不带认证,私有源台标回落占位图;②音频在不相关主机(第三方 CDN)上时不带凭据;
  ③跨主机 302 是否转发 `Authorization` 随平台未断言;④`http://` 明文源上传的是明文口令。
  ⚠️ 验收:Apple 共享层探针 56/56(两台夹具:全站 Basic + 只认 UTF-8);Android / 鸿蒙 / iOS 过编译门,
  **三端 401 弹框的点击流程尚未实跑**(本机无鸿蒙设备)。逐条见 `docs/TROUBLESHOOTING.md` H253。

## 六、下载离线

- 单集离线下载,进度展示;播放时优先本地文件,无则回落流式
- **视频来源的单集不提供下载**(1.0.6):下载是长期占盘、需要你自己管理的动作,而视频来源的音频地址本身约两小时失效、背后也不是"发布方托管的一集"。所以下载键在视频单集上置灰(带无障碍说明),**自动缓存照旧生效** —— 缓存是"听过就留在本机"的临时层,受字节预算约束、可一键清除,两者不冲突
- **播放缓存**(与上一条是两回事):首次在线播放某一集时,后台从同一地址把**整集**取回本机,下次直接从本地文件起播、不再联网。字节预算 300 MB,超出按「最久没听的先淘汰」;与下载**目录分开、账本分开、清理入口分开**,预算淘汰永不触碰用户显式下载的那份。电台流不缓存
- **断网可浏览**:已经加载过的列表文字走各自的磁盘缓存(榜单 + 频道详情),**封面图片另有一层磁盘缓存** —— 这一层是 1.0.5 新增的,因为鸿蒙原本一张图都没落盘,断网进发现页会看到整屏空白格。预算 20 MB,同样按最久没用的淘汰;不计蜂窝闸门
- 下载用量统计;删除单集 / 清空全部下载

- **同步哪六样**:订阅、收藏、听觉印记、批注、播放历史、收听统计。**下载与设置不参与** ——
  下载是逐设备的大文件,设置里含设备特定的路径/语言选择,合并只会造成"看起来同步了其实没有"。
- **双向并集**:不是"谁覆盖谁"。两端跑完拿到同样的内容;订阅按规范化 feed URL 去重。
- **只走局域网**:mDNS 发现(`_reverb._tcp`,系统 NSD + 一条 QU 单播兜底)+ 手动 `IP:端口` 兜底;
  数据用**每次配对现生成的 P-256 会话密钥**做 ECDH → HKDF-SHA256 → AES-256-GCM 加密,
  不经过任何服务器、不需要账号。六位配对码由共享密钥派生,由人核对 ——
  这是这套方案唯一的中间人判据(没有证书体系)。因为密钥不跨配对复用,**同一对设备每轮配对的
  配对码都不同**(2026-11-13 真机:连续两轮 `974 870` → `020 444`;修复前连续三轮都是 `897 003`,见 H278)。
  手动兜底不写端口时按 `47820` 连(2026-11-13 真机验过:`192.168.6.228` → 默认端口,配对通过)。
- **删除传播(2026-11-12 起)**:取消订阅、取消收藏、删印记、删批注会记一条**墓碑**
  (`kind + id → deletedAt`,保留 90 天),随快照的 `tombstones` 一段传给对端;对端合并时
  先按墓碑删本地,再过滤快照里的同名条目。本地**重新添加**同一项会清掉墓碑;
  从备份恢复回来的条目也算重新添加(`addAll` 里清),否则下一次同步会把它再删一遍。
  订阅的墓碑键是**归一化 feedUrl**(与去重同一判据),不是频道 id。
  **已知边界**:墓碑优先于对端快照里的同一条目 —— A 删除、B 在同步前重新订阅,这一次仍会被删掉;
  订阅与收藏没有 `updatedAt`,"重新添加比删除更晚"无法证明,彻底解决要 HLC(见研究文档 §5)。
  历史与收听统计不参与墓碑:前者 LWW、后者按设备取 max,没有"删一条"的语义。
- **打开才监听**:面板关掉就停 socket,不后台常驻;不做锁屏/后台自动接力。两端同时点对方时,
  后到的一方会看到失败提示,重试即可(同一时刻只跑一个会话)。
- **播放交接(2026-11-15,四端)**:同步完成后,同一条已加密的 TCP 会继续留着,变成本次面板的
  「交接通道」—— 握手帧里带 `live: true`,老版本忽略这个键、同步完照旧断开。两端都停在这个面板时,
  正在播放的一方每秒把「哪一集、播到哪、是否在播、倍速」发给对方(暂停 / 跳转 / 换集立刻补一条),
  另一台面板显示「另一台设备正在播放 / 暂停在这一集 … · 12:34」,并出现「在此设备继续」。
  点下去的顺序是固定的:**播放方先暂停并回一条带最终位置的 `taken`,请求方再按
  `位置 + 这次往返的一半 × 倍速`(最多到整集结束前 1.5 秒)seek 起播** —— 所以两端不会同时出声,
  也不存在「自动接管 / 自动播放」。位置外推用 ping-pong 时钟估计(5 个样本取中位数;
  少于两份样本或往返 > 2 秒就不外推,界面写「约 12:34」)。直播流不参与交接;
  面板关掉 socket 就断,不后台常驻。
- **发现失败不等于功能坏了**:访客 Wi-Fi、AP 隔离、企业网络会让组播到不了对端,
  有的 AP 甚至只放行一个方向的组播(H3C 实测);面板上永远显示本机地址,
  手动输入对方地址照样能连。

## 已知 / 未做

- **应用内升级**:Android 自 1.0.5 起有(查 GitHub Releases 公开接口 → 下载 → 交系统安装器,默认只在 Wi-Fi 下自动下载);macOS 自 1.0.6 起有同一条查询(下载 dmg 后由用户自己打开安装,不自装;只按版本名判新旧,同版本重出包不提示);鸿蒙由应用市场负责。
- **macOS 真实频谱**:受平台限制无法像 Android 那样抓取系统混音做 FFT,故 macOS 一律用程序化水墨动效替代。
- **鸿蒙真实频谱**:同样无对等手段 —— `SOURCE_TYPE_PLAYBACK_CAPTURE` 自 API 12 废弃,
  官方改用 native 的 `OH_AVScreenCapture`(需录屏授权),为一个封面动效索取录屏权限不成比例,
  故与 macOS 一致走程序化水墨动效,设置页不出现该开关。
- **macOS 后台更新**:无 WorkManager 式后台巡检,订阅更新通过「最新」手动刷新聚合。
- **macOS 无障碍标注**:`Image(systemName:)` 41 处、`accessibilityLabel` **0 处** ——
  Android 与鸿蒙 2026-10-06 已把图标型可点控件标注补齐,桌面端是同一族缺口的更大一份。
  **本轮只在双端补,macOS 没动**:本机跑不了它的构建也起不了它的应用(AGENTS.md「macOS」一节六层实测),
  改了无法验;SwiftUI 里图标按钮的标注是否被 VoiceOver 取到同样只能实听,所以按硬规矩如实登记而不是盲补。
